# Cortex Metrics Long-Term Storage Helm Chart (`cortex`)

## 1. Overview & Problem Statement

Standard **Prometheus** instances store time-series metrics in an ephemeral local Time Series Database (TSDB) on disk. In high-scale or multi-cluster environments:
- Local disk retention is limited (e.g., 7 to 15 days) due to storage capacity and I/O costs.
- Queries across multiple clusters require aggregating disparate Prometheus endpoints manually.
- If a Prometheus node crashes or its volume corrupts, historical monitoring data is lost permanently.

**Cortex** solves this by providing horizontally scalable, multi-tenant, long-term metric storage backed by cheap, durable object storage (such as **AWS S3**). It implements a remote-write endpoint compatible with Prometheus, allowing Prometheus instances from multiple clusters (PrimaryHub, SecondaryHub, Spokes) to stream time-series data into a centralized, durable repository.

In 01-Sandbox, the `cortex` chart packages a hardened, single-binary architecture fronted by an **NGINX TLS 1.2/1.3 reverse proxy** with dynamic `.htpasswd` Basic Authentication, strict per-role path routing, strict sample ingestion limits, and S3 block storage.

## 2. Core Kubernetes Concepts Explained for Beginners

- **Single-Binary Architecture:** Cortex runs with `-config.file=cortex.yaml` and `target: all`, meaning all internal microservice roles (Distributor, Ingester, Store Gateway, Querier, Compactor) run in a single process. Suitable for 01-Sandbox scale; can be split into separate deployments for hyperscale.
- **Deployment Strategy: `Recreate`:** Unlike `RollingUpdate`, `Recreate` terminates all existing pods before starting new ones. Used here because Cortex with a single-instance PVC (ReadWriteOnce) cannot have two Cortex processes sharing the same WAL directory simultaneously.
- **Two Secrets, Two Roles:** The chart generates two separate Secret objects:
  - `cortex-tls-secret` (`kubernetes.io/tls`): TLS certificate and key auto-generated by Helm using `genSignedCert` with SANs for `127.0.0.1`, `10.99.0.50`, and cluster-local DNS names.
  - `cortex-auth-secret` (`Opaque`): The `.htpasswd` file (bcrypt-hashed credentials), plus plaintext `writer-password` and `reader-password` fields used by rotation scripts.
- **Dynamic `.htpasswd` Rotation:** NGINX reads `.htpasswd` on every incoming HTTP request. The Kubernetes Secret volume is kept mounted as a whole directory (not `subPath`) so kubelet's volume reconciliation dynamically updates the file when the Secret is patched — zero pod restart needed.
- **RBAC: Role-Based (Namespace-Scoped):** The `cortex-auth-rotator` ServiceAccount has only a namespaced `Role` (not ClusterRole), permitting `get`, `patch`, `update` on exactly one Secret (`cortex-auth-secret`) within the `cortex` namespace.

## 3. Template-by-Template Manifest Breakdown

The templates in [codeInspector/charts/cortex/templates/](file:///home/berrybytes/Desktop/Kamal/01-Sandbox/codeInspector/charts/cortex/templates/) deploy:

### 3.1. [deployment.yaml](file:///home/berrybytes/Desktop/Kamal/01-Sandbox/codeInspector/charts/cortex/templates/deployment.yaml)
- **Kind:** `Deployment` (`apps/v1`), namespace: `.Release.Namespace` (resolved at deploy time, not from values).
- **Strategy:** `type: Recreate` — required for single-node WAL disk safety.
- **Container 1 — `cortex`:** `cortexproject/cortex:v1.18.0`
  - Arg: `-config.file=/etc/cortex/cortex.yaml`
  - Ports: `9009` (http-internal), `9095` (grpc-internal)
  - Mounts: `cortex-config` ConfigMap (single file `cortex.yaml` via `subPath`) + `cortex-storage` PVC at `/var/lib/cortex`
  - Probes: exec `wget -q http://127.0.0.1:9009/ready`
- **Container 2 — `nginx-proxy`:** `nginx:alpine`
  - Port: `8443` (https-gate)
  - Mounts: `nginx-config` (ConfigMap `cortex-config`, subPath `nginx.conf`), `tls-certs` (Secret `cortex-tls-secret`), `auth-secret` (Secret `cortex-auth-secret`)
  - ReadinessProbe: HTTPS GET `/ready` on port 8443

### 3.2. [configmap.yaml](file:///home/berrybytes/Desktop/Kamal/01-Sandbox/codeInspector/charts/cortex/templates/configmap.yaml)
- **Kind:** `ConfigMap`, name: `cortex-config`, namespace: `.Release.Namespace`.
- **Keys:**
  1. `cortex.yaml`: Full Cortex configuration including `target: all`, `auth_enabled`, `server` block (HTTP 9009, gRPC 9095), `limits` block (all 9 tuneable limits from `values.yaml`), `blocks_storage` (S3 config, TSDB dir, 2h block ranges), `distributor`/`ingester`/`memberlist`/`store_gateway`/`compactor` blocks.
  2. `nginx.conf`: NGINX config with `map $remote_user $is_authorized` block, SSL settings (TLS 1.2+1.3, strong ciphers, prefer server ciphers), and two location blocks:
     - `POST /api/v1/push` — requires `$is_authorized == 1` (cortex-writer-* prefix)
     - `GET /prometheus/` — requires `$is_authorized == 2` (grafana-reader-* prefix)

### 3.3. [secret.yaml](file:///home/berrybytes/Desktop/Kamal/01-Sandbox/codeInspector/charts/cortex/templates/secret.yaml)
- **Generates two Secrets:**
  1. **`cortex-tls-secret`** (`kubernetes.io/tls`): Self-signed TLS certificate generated via Helm's `genCA` + `genSignedCert` functions. Valid for 730 days (2 years). SANs include `127.0.0.1`, `10.99.0.50`, and multiple cluster-local DNS hostnames.
  2. **`cortex-auth-secret`** (`Opaque`): Contains three keys:
     - `.htpasswd`: Two lines generated with Helm's `htpasswd` function (bcrypt) for writer and reader.
     - `writer-password`: Plaintext writer password (used by rotation scripts to compare/update).
     - `reader-password`: Plaintext reader password.

### 3.4. [rbac-rotator.yaml](file:///home/berrybytes/Desktop/Kamal/01-Sandbox/codeInspector/charts/cortex/templates/rbac-rotator.yaml)
- **Kinds:** `ServiceAccount`, `Secret` (service-account-token), `Role`, `RoleBinding`.
- **ServiceAccount:** `cortex-auth-rotator` with a `kubernetes.io/service-account-token` Secret named `cortex-auth-rotator-token`.
- **Role `cortex-auth-rotator-role`:** Namespace-scoped, grants `get`, `patch`, `update` on exactly `cortex-auth-secret`. No other permissions.

### 3.5. [pvc.yaml](file:///home/berrybytes/Desktop/Kamal/01-Sandbox/codeInspector/charts/cortex/templates/pvc.yaml)
- **Kind:** `PersistentVolumeClaim`, name: `.Values.persistence.pvcName` (`cortex-data-pvc`).
- **Requests:** `.Values.persistence.size` (default `30Gi`) on storageClass `.Values.persistence.storageClass` (`standard`).

### 3.6. [service.yaml](file:///home/berrybytes/Desktop/Kamal/01-Sandbox/codeInspector/charts/cortex/templates/service.yaml)
- **Kind:** `Service`, name: `cortex-service`.
- **Exposes:** Port `8443` (HTTPS NGINX gate), NodePort `30443` for WireGuard mesh access from remote clusters.

## 5. Architectural Role in the 01-Sandbox Ecosystem

- **Central Multi-Region Metric Aggregator:** Receives remote_write from PrimaryHub, SecondaryHub, and Spokes over the WireGuard overlay (`10.99.0.50:30443`).
- **Role-Based Endpoint Separation:** NGINX enforces strict path authorization — only `cortex-writer-*` users can write; only `grafana-reader-*` users can read. This prevents Prometheus scrapers from accidentally querying and Grafana dashboards from accidentally pushing.
- **Automated Zero-Downtime Credential Rotation:** The `cortex-rotator` CronJob on PrimaryHub patches `cortex-auth-secret`, appending a new timestamped user (`cortex-writer-<timestamp>`) while the old credentials remain valid through a 10-minute grace period. Because NGINX reads `.htpasswd` per-request (no caching), the transition is seamless.

## 6. Practical Debugging & Troubleshooting

### Check Pod & Container Health
```bash
# Check pod status (should show 2/2 READY containers)
kubectl get pods -n cortex
kubectl describe pod -l app=cortex -n cortex

# Stream Cortex engine logs
kubectl logs -n cortex -l app=cortex -c cortex -f --tail=100

# Stream NGINX proxy access and error logs
kubectl logs -n cortex -l app=cortex -c nginx-proxy -f --tail=100
```

### Test Authentication & Endpoints
```bash
# Test push endpoint (should return 204 No Content with empty payload)
curl -k -u cortex-writer:CortexWriterSecret2026! \
  https://<node-ip>:30443/api/v1/push -X POST -d '' -v

# Test Cortex readiness
curl -k -u cortex-writer:CortexWriterSecret2026! https://<node-ip>:30443/ready

# Check htpasswd contents on the live cluster
kubectl get secret cortex-auth-secret -n cortex \
  -o jsonpath='{.data.\.htpasswd}' | base64 -d
```

### Common Failure Modes
1. **HTTP 401 Unauthorized:** Credentials in Prometheus `remoteWrite.basic_auth` or Grafana datasource do not match `.htpasswd`. Verify the secret contents as shown above.
2. **HTTP 403 Forbidden — Wrong role:** A `grafana-reader-*` user attempting a write (or vice versa). Check that the username prefix matches the NGINX map block logic.
3. **HTTP 429 Too Many Requests / `ingestion rate limited`:** `limits.ingestionRate` is too low for the cluster scale. Increase `ingestionRate` and `ingestionBurstSize` in values, then `helm upgrade`.
4. **S3 Upload Failures:** Cortex pods cannot authenticate to S3. Verify the EC2 instance's IAM Role has `s3:PutObject`, `s3:GetObject`, and `s3:ListBucket` on the bucket ARN.
5. **Deployment stuck in `Pending` (new rollout):** Because strategy is `Recreate`, the old pod must fully terminate before the new one starts. If the old pod's PVC does not detach, it will block. Check `kubectl describe pvc cortex-data-pvc -n cortex`.
